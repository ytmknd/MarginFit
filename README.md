# MarginFit

印刷用下絵（PDF / PNG）の **用紙サイズ・余白・下絵の位置** を、物理寸法（mm）で正確に調整する Web アプリです。

> All processing is performed locally in your browser.
> 読み込んだファイルはブラウザ内だけで処理され、外部サーバーへは送信されません。

---

## MarginFit とは

賞状などの既存用紙をスキャナー（600 dpi 程度）で取り込むと、

- 左右・上下の余白が微妙にずれる
- スキャン画像のキャンバスが実物より少し小さい／大きい
- PDF 化したときのページサイズが実物と一致しない

といった問題が起こります。MarginFit は、下絵の **出力ファイルそのもの**（PDF の MediaBox、PNG のピクセル数と DPI メタデータ）を、指定した mm 寸法どおりに作り直すツールです。画面上の見た目を変えるだけのツールではありません。

主な機能

| 機能 | 内容 |
| --- | --- |
| 用紙サイズ | 任意サイズ（0.1 mm 単位）、A4 縦／横プリセット、中央基準／左上基準 |
| 余白 | 上下左右ごとに追加・削除（mm / px）、直接指定、負の値＝切り取り |
| 揃える | 左右の余白を同じに／上下の余白を同じに／内容を用紙中央に配置（用紙サイズは不変） |
| 全方向同じ余白 | 4 辺を同じ余白にして用紙サイズを再計算 |
| 移動 | 矢印ボタン（0.1 mm、Shift で 1 mm）、キーボード矢印キー、移動量の数値指定 |
| 拡大縮小 | 下絵自体の拡大縮小（100.000 % 既定、縦横比固定が標準）。余白機能とは別 |
| ガイド | 用紙中央線（縦・横）、余白、下絵境界、用紙境界（出力には含まれない） |
| Calibration | 画面上の 10 mm 方眼・100 mm 線、および 100 mm 線入りの Calibration PDF 生成 |
| 履歴 | Undo / Redo / Reset（Ctrl+Z / Ctrl+Y） |
| 出力 | PNG → PNG（DPI 保持・ロスレス）、PNG → PDF、PDF → PDF（再ラスタライズなし） |

## AwardPrint との関係

MarginFit は、賞状差し込み印刷アプリ **AwardPrint** の前処理ツールです。

1. スキャンした賞状の PNG（または PDF）を MarginFit で読み込む
2. 実物の用紙サイズ（例: 216.3 × 297.0 mm）と余白・位置を合わせる
3. PDF（または PNG）で保存する
4. そのファイルを AwardPrint の下絵として読み込む

出力 PDF のページサイズ（MediaBox / CropBox）は指定した mm 値そのものなので、AwardPrint で「100% 表示」したときの物理サイズは MarginFit で指定したサイズと一致します。印刷時は必ず「実際のサイズ／100%」を使用してください（「用紙に合わせる」は不可）。

## 起動方法

Node.js 20 以降が必要です（開発時は Node.js 24 で確認）。

```bash
npm install
npm run dev        # 開発サーバー http://localhost:5173/
```

## ビルド方法

```bash
npm run build      # 型チェック + dist/ に静的ファイルを出力
npm run preview    # ビルド結果をローカルで確認
npm test           # 単体テスト（vitest）
```

`dist/` は相対パス（`base: './'`）でビルドされるため、任意の静的 Web サーバーやサブディレクトリにそのまま配置できます。サーバー側の処理は一切不要です。
（`file://` で直接開くと Web Worker と PDF.js のワーカーがブラウザの制限で読み込めないため、何らかの HTTP サーバーから配信してください。）

### 座標モデル（プレビューと出力の共通化）

内部状態は「用紙サイズ（mm）」「用紙左上から見た下絵左上の位置（mm）」「拡大率」だけです。上下左右の余白はこれらから導出します（負の値は切り取り）。

`geometry.ts` の `computeLayout()` がこの状態を具体的な配置に変換し、

- 画面プレビュー（Viewer）
- PNG 出力（ピクセル配置）
- PDF 出力（`toPdfPlacement()` で pt に変換）

のすべてが同じ結果を使います。そのため「プレビューでは合っているのに保存するとずれる」ことは起きません。内部値は float64 のまま保持し、丸めは表示時と、整数が物理的に必要な箇所（PNG のピクセル数・配置、pHYs 値）でのみ行います。

## PDF 処理方法

- **PDF → PDF**: 元ページを pdf-lib の `embedPage` で Form XObject として新しいドキュメントに埋め込み、指定サイズの新ページ（MediaBox = CropBox = 指定 mm）に、平行移動（＋必要なら拡大縮小）の変換行列 1 つで描画します。元のコンテンツストリームとリソース（ベクター、文字、画像）はそのままコピーされ、**再ラスタライズしません**。
  - 元ページの CropBox（なければ MediaBox）を表示範囲として扱います。
  - `/Rotate`（90/180/270°）付きのページは、ビューアでの表示向きのまま配置されるよう変換行列で補正します。
  - `/UserUnit`（ページ単位の拡大、PDF 1.6）付きのページは「ボックス寸法 × UserUnit」を実寸として扱い、出力では通常の単位（1/72 inch）のページに UserUnit 倍で描画します。
  - 用紙外にはみ出した部分は新しいページの境界で切り取られます。
- **PNG → PDF**: PNG の IDAT（zlib 圧縮データ）を **そのまま** PDF の画像 XObject（FlateDecode + PNG predictor）として埋め込みます。再圧縮も再サンプリングもないビット単位で同一の画像です。透過・インターレース PNG は pdf-lib の `embedPng`（こちらもロスレス）で埋め込みます。画像は `(ピクセル数 / DPI) × 72 pt` の大きさで配置されます。
- 複数ページ PDF はページを選択して編集し、そのページだけを 1 ページの PDF として出力します。

## PNG DPI 処理方法

- 読み込み時に `pHYs` チャンク（単位 = メートル）から DPI を読み取ります。DPI 情報がない場合は 600 dpi と仮定し、ユーザーが変更できます。
- pHYs は「1 メートルあたりのピクセル数（整数）」で保存されるため、600 dpi は `round(600 / 0.0254) = 23622` ppm として書き込まれ、読み戻すと 599.9988 dpi になります。読み込み時は、整数 ppm の量子化誤差の範囲で整数 DPI に一致する場合、その整数値（600）として扱います。
- 出力 PNG には必ず pHYs を書き込みます（既存の pHYs は削除し、IHDR の直後に挿入、CRC も再計算）。Canvas の `toBlob()` は DPI 情報を保持しないため、Canvas 経由の場合も出力後にチャンクを書き換えます。

### ロスレス出力

拡大率 100 % のとき（通常の使い方）、PNG 出力は Canvas を使いません。

1. 元 PNG の IDAT を展開し、フィルタを解除して生の走査線を得る
2. 新しい用紙サイズの走査線バッファを背景色（白 / 透明）で作り、元画像の画素を **バイト単位でそのまま** 指定位置へコピー（はみ出した部分は切り取り）
3. 行ごとに最適な PNG フィルタを選んで再圧縮

このため、画素値・カラータイプ（グレー / RGB / パレット / α 付き）・ビット深度（8 / 16 bit）・色管理チャンク（gAMA, cHRM, sRGB, iCCP 等）が保持されます。色変換も再サンプリングも起きません。

拡大縮小しているとき、または 1/2/4 bit・インターレース等の特殊な PNG のときだけ、Canvas で描画します（この場合は 8 bit RGBA になります）。

## 単位換算

| 換算 | 式 |
| --- | --- |
| inch ↔ mm | 1 inch = 25.4 mm（定義値） |
| inch ↔ pt | 1 inch = 72 pt（PDF のユーザー空間単位） |
| mm → pt | `pt = mm × 72 / 25.4` |
| pt → mm | `mm = pt × 25.4 / 72` |
| mm → px | `px = mm × dpi / 25.4` |
| px → mm | `mm = px × 25.4 / dpi` |
| dpi → ppm (pHYs) | `ppm = round(dpi / 0.0254)` （600 dpi → 23622、300 dpi → 11811） |

例: A4（210 × 297 mm）= 595.276 × 841.890 pt = 600 dpi で 4960.63 × 7015.75 px → 4961 × 7016 px。

単位換算テスト（`src/lib/__tests__/units.test.ts`）では、mm → pt → mm、mm → px → mm（300 dpi / 600 dpi）の往復誤差が 1e-12 mm 未満であること、整数ピクセルへの丸め誤差が半ピクセル以内であること、pHYs 値の往復などを検証しています。

## 既知の制限事項

- **PNG のサイズは整数ピクセル**です。指定した mm 値に対し、PNG の実寸は最大 ±0.5 ピクセル（600 dpi で ±0.021 mm）ずれることがあります（画面右側の「PNG実寸」に表示）。PDF 出力のページサイズは指定値どおりです。
- 同様に PNG 由来の下絵の位置は整数ピクセル単位（600 dpi で 0.042 mm）に丸められます。0.1 mm ずつ移動すると 2 px / 3 px ずつ交互に動きますが、累積位置は正確に保たれます。
- 拡大縮小を行うと PNG の画素は再サンプリングされ、8 bit RGBA で出力されます。
- PDF → PDF では元ページを Form XObject として埋め込むため、注釈（リンク、フォームフィールド等）は引き継がれません。暗号化（パスワード保護）された PDF は読み込めません。
- 透明背景は PNG 出力のみです。PDF の背景は白（用紙色）です。透明背景はα付き PNG 以外では Canvas 経由の出力になります。
- 画面上の「100%」表示は CSS の 96 dpi 基準のため、モニターによって実寸とは一致しません。実寸の確認は Calibration PDF を印刷して定規で測ってください。
- 1 つの PNG の出力サイズはブラウザの Canvas 上限（一辺 32767 px、約 2.68 億画素）を超えられません。
- 画面の PDF プレビューは PDF.js によるラスター表示です（出力には影響しません）。
- `pHYs` の縦横 DPI が異なる PNG は横方向の DPI を使用します。
